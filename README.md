# 📈 ETF Volatility Analyzer: Python Concurrency & Parallelism Demo

โปรเจกต์นี้จัดทำขึ้นเพื่อทดลองและทำความเข้าใจการเขียนโปรแกรมแบบทำงานพร้อมกัน (Concurrency และ Parallelism) ในภาษา Python โดยนำเสนอผ่านระบบจำลอง **"การดึงข้อมูลและวิเคราะห์ความผันผวนของกองทุน ETF"** โปรแกรมจะแบ่งการทำงานออกเป็น 3 ขั้นตอนหลัก ซึ่งแต่ละขั้นตอนจะเลือกใช้เครื่องมือที่แตกต่างกัน (`asyncio`, `threading`, `multiprocessing`) ตามความเหมาะสมของลักษณะงาน (I/O-bound vs CPU-bound)


## 🛠️ สถาปัตยกรรมและเครื่องมือที่ใช้

ระบบนี้จำลองการทำงานเป็นท่อส่งข้อมูล (Pipeline) โดยแบ่งหน้าที่ดังนี้:

### 1. การดึงข้อมูล API (Network I/O) -> เลือกใช้ `asyncio`
* **หน้าที่ในโค้ด:** ฟังก์ชัน `fetch_etf_data()` จำลองการดึงราคาปิดย้อนหลังของกองทุน (เช่น VOO, QQQ, VTI) ผ่านเครือข่ายอินเทอร์เน็ต
* **ทำไมถึงใช้ Asyncio:** การยิง API เป็นงานประเภท I/O-bound ที่ต้อง "รอ" เซิร์ฟเวอร์ตอบกลับ `asyncio` ทำงานบน Single Thread แต่มี Event Loop ที่ดีมาก เมื่อส่งคำขอของกองทุน A ไปแล้ว แทนที่จะหยุดรอ โปรแกรมจะสลับไปส่งคำขอของกองทุน B และ C ทันที ทำให้ประหยัดเวลาและใช้ทรัพยากรน้อยที่สุด

### 2. การบันทึกข้อมูลลงไฟล์ (Disk I/O) -> เลือกใช้ `ThreadPoolExecutor`
* **หน้าที่ในโค้ด:** ฟังก์ชัน `save_to_csv()` นำข้อมูลที่ดึงมาได้ ไปจำลองการเขียนลงไฟล์นามสกุล `.csv`
* **ทำไมถึงใช้ Threading:** การเขียนไฟล์ลงฮาร์ดดิสก์เป็นงาน I/O-bound เช่นกัน แม้ Python จะมี GIL ที่ล็อกการประมวลผล CPU ไว้ทีละ Thread แต่สำหรับการรออ่าน/เขียนไฟล์ (OS-level operations) ระบบจะอนุญาตให้ Threads อื่นๆ ทำงานสลับกันไปมาได้ การแตก Thread จึงช่วยให้เซฟไฟล์หลายๆ ตัวพร้อมกันได้เร็วขึ้น

### 3. การคำนวณสถิติ (CPU-bound) -> เลือกใช้ `ProcessPoolExecutor`
* **หน้าที่ในโค้ด:** ฟังก์ชัน `calculate_volatility()` จำลองการคำนวณสมการคณิตศาสตร์ที่ซับซ้อนเพื่อหาค่าความผันผวนของแต่ละกองทุน
* **ทำไมถึงใช้ Process Pool:** งานประมวลผลตัวเลขหนักๆ จะกินทรัพยากร CPU เต็มที่ หากใช้ Threading จะถูก GIL บล็อกให้ทำได้ทีละงาน การใช้ `ProcessPoolExecutor` จะทำการจำลอง (Fork) โปรแกรมของเราแยกออกไปรันบน CPU Cores อื่นๆ อย่างอิสระ (1 Process มี GIL และ Memory เป็นของตัวเอง) ทำให้คำนวณทุกกองทุนคู่ขนานกันไปได้จริงๆ (True Parallelism)
